# Prettier Formatting Patterns

## When to use
Apply these patterns when formatting TypeScript source files, fixing lint errors, or ensuring code style consistency before committing.

## Patterns

### Format only hand-written source files
```bash
npx prettier --write \
  "credentials/**/*.ts" \
  "nodes/Commercetools/*.ts" \
  "nodes/Commercetools/utils/**/*.ts" \
  "scripts/**/*.ts"
```
Explicitly targets source directories — avoids touching `generated/` files.

### Check formatting in CI without writing
```bash
npx prettier --check "**/*.ts" --ignore-path .gitignore
```
Exits non-zero if any file is out of format. Use in pre-commit or CI steps.

### Full lint + format fix in one pass
```bash
npm run lint:fix
```
Runs ESLint (with `eslint-plugin-prettier`) to fix both style and formatting together. Preferred over running Prettier directly on the whole repo.

## Pitfalls

- **Never format `nodes/Commercetools/generated/*.ts`** — these are auto-generated by `npm run generate` and will be overwritten on the next run. Manual formatting changes will be lost.
- Tabs, not spaces — editors that auto-convert tabs to spaces will cause persistent lint failures. Confirm your editor respects `.editorconfig` or the project's tab setting.
