## User Journey — Critical Activation Path

```
1. Install node (npm install n8n-nodes-commercetools)
2. Add credential → fill Project Key, Region, Client ID/Secret, Scopes
   └─ Optional: select Event Provider → fill AWS or GCP sub-fields
3. Add Commercetools (Action) node → select Resource → select Operation
   └─ Fill in required fields → execute
4. Add Commercetools Trigger node → select Events → activate workflow
   └─ Subscription created on commercetools → cloud infra provisioned (if AWS/GCP)
5. First webhook event received → workflow runs
```

## Key Patterns from This Codebase

### n8n INodeProperties patterns
```typescript
// Hint/notice pattern
{
  displayName: 'Important',
  name: 'notice',
  type: 'notice',
  default: '',
  displayOptions: { show: { eventProvider: ['aws'] } },
  description: 'AWS costs may apply. Ensure your n8n instance has a public URL.',
}

// displayOptions gating — show field only when relevant
displayOptions: {
  show: {
    resource: ['product'],
    operation: ['update'],
  },
}

// placeholder and hint on string fields
placeholder: 'e.g. my-project-key',
hint: 'Found in Merchant Center → Settings → Project settings',
```

### Generated files — edit the script, not the output
- `nodes/Commercetools/generated/properties.ts` — generated by `scripts/generateProperties.ts`
- `nodes/Commercetools/generated/subscription.properties.ts` — generated by `scripts/generateSubscriptionProperties.ts`
- Direct edits to generated files are overwritten on next `npm run generate`
- For one-off UX fixes (notices, descriptions on non-generated params), edit `Commercetools.node.ts` or `CommercetoolsTrigger.node.ts` directly

### Credential form conventions
- File: `credentials/CommerceToolsOAuth2Api.credentials.ts`
- AWS sub-fields shown only when `eventProvider === 'aws'` via `displayOptions`
- GCP sub-fields shown only when `eventProvider === 'gcp'`
- The `serviceAccountJson` field must accept full JSON blob — do not split into sub-fields

### Error messaging surfaces
- User-facing errors use `NodeOperationError(this.getNode(), 'message')`
- API errors use `NodeApiError`
- Both appear in the n8n execution panel — keep messages actionable and specific

## CRITICAL for This Project

1. **Do not edit generated files directly.** Changes to `nodes/Commercetools/generated/` are overwritten by `npm run generate`. Trace UX improvements to their generator in `scripts/`.
2. **Credential field for GCP must remain a single JSON blob field.** n8n's encrypted storage mangles PEM line breaks if split into individual fields — never propose splitting `serviceAccountJson`.
3. **Empty `messages[]` or `changes[]` arrays crash the subscription.** Do not propose UI that allows submitting zero events on the trigger — enforce at least one event selected.
4. **The update action builder (fixedCollection) is auto-generated.** Field labels and descriptions for action types come from `scripts/generateProperties.ts` → `actionBodyFields`.
5. **Preserve TypeScript strict mode.** Any code changes must compile under `tsconfig.json` strict settings.
6. **Use tabs, single quotes, 100-char line width** per `.prettierrc.js` — match the existing code style in all edits.
7. **The node targets n8n 1.x API.** Use `INodeType`, `IExecuteFunctions`, `IWebhookFunctions` — not community patterns from older n8n versions.
